## 英文摘要

SGX-PFS is the state-of-the-art secure storage solution for Trusted Execution Environment (TEE). SGX-PFS uses Merkle Hash Trees (MHT) to achieve confidentiality, integrity, and freshness, and adopts a recovery journal to ensure crash consistency. Unfortunately, SGX-PFS is vulnerable to a new type of eviction attacks: a privileged adversary can capture transient on-disk states (referred to as snapshots), which are generated by cache evictions inside the TEE (invisible and unanticipated to the user) and can potentially result in security loopholes.

Snapshots are allowed mainly because neither the POSIX file system interface nor the block interface has constraints on the ordering and timing for the persistence of writes. To address this vulnerability, we propose a new security property called sync atomicity, which promises that all writes before a sync request are committed in an all-or-nothing manner. We further design a secure virtual disk (called AtomicDisk) by enhancing SGX-PFS. AtomicDisk achieves sync atomicity by introducing an internal commit operation, so that evicted (uncommitted) writes can be distinguished from synced (committed) writes, thus effectively preventing eviction attacks. We compare AtomicDisk to SGX-PFS with trace-driven workloads. SGX-PFS generates hundreds of thousands of snapshots being vulnerable to eviction attacks. In contrast, AtomicDisk correctly generates exactly one valid state (caused by a sync), while achieving better performance than SGX-PFS.

## 中文摘要

SGX-PFS 是面向可信执行环境（TEE）的最先进安全存储方案。它使用 Merkle 哈希树（MHT）实现机密性、完整性与新鲜性，并采用恢复日志保证崩溃一致性。然而，SGX-PFS 易受一类新型逐出攻击的影响：特权对手可以捕获 TEE 内部 cache 逐出所产生的瞬态盘上状态（称为快照），这些状态对用户不可见且不可预期，并可能导致安全漏洞。允许快照存在的主要原因是，POSIX 文件系统接口与块接口都没有约束写持久化的顺序与时机。为修复这一漏洞，本文提出一种新的安全属性——sync 原子性，它保证 sync 请求之前的所有写以 all-or-nothing 方式提交。本文进一步通过增强 SGX-PFS 设计了一个安全虚拟磁盘 AtomicDisk。AtomicDisk 通过引入内部提交操作实现 sync 原子性，从而把逐出的（未提交）写与已同步的（已提交）写区分开，有效防止逐出攻击。本文用 trace 驱动的负载比较 AtomicDisk 与 SGX-PFS。SGX-PFS 会产生数十万个易受逐出攻击的快照；相比之下，AtomicDisk 正确产生恰好一个有效状态（由一次 sync 引起），同时性能优于 SGX-PFS。

## 一句话总结

> CIFC 还不够：TEE 分不清用户 sync 出的磁盘状态与 cache 逐出留下的瞬态快照，所以还需要一条 sync 原子性。

## 研究背景与问题

- **TEE 只保护内存**：TEE 硬件保护内存与 CPU 状态，盘上数据仍要由 TEE 软件保护；对手是特权、在线、主动的，能监听、篡改、回滚数据，也能让主机崩溃。
- **Linux 现成手段不达标**：eCryptFs、fscrypt、dm-crypt、dm-integrity 都不是为 TEE 设计的，dm-crypt 加 dm-integrity 只提供机密性与完整性，缺少新鲜性与一致性。
- **SGX-PFS 也不够**：它用 MHT 与 recovery journal 做到保密性、完整性、新鲜性与一致性，但仍受逐出攻击（eviction attack）影响——攻击者可以抓取由 TEE 内部 cache 逐出产生、用户不可见也未预期的瞬态盘上状态（vulnerable snapshot）并重放。作者用这种快照拿到了 SGX 保护的 Redis 服务器的完全访问权，Intel 已确认该问题。
- **根因在接口**：POSIX 文件系统接口与块接口都没有约束写持久化的顺序与时机，所以“用户 sync 出来的状态”与“逐出留下的中间态”在盘上无法区分。

## 核心贡献

- **发现并命名逐出攻击**：指出在机密性、完整性、新鲜性、一致性之外还缺一条属性，否则特权对手可以用瞬态快照做重放。
- **提出 sync 原子性（sync atomicity）**：sync 请求之前的所有写以 all-or-nothing 方式提交，当且仅当 sync 完成时才算提交，使 TEE 无论是否发生逐出都能识别用户已同步的磁盘状态。
- **实现安全虚拟盘 AtomicDisk**：在 MHT 保护的 SGX-PFS 上引入由 sync 触发的内部提交，区分未提交的逐出写与已提交的同步写，恢复时只回放后者。
- **对上层透明**：不修改应用与文件系统，保持标准块 I/O 接口（read、write、flush），原型集成在 SGX 的 Occlum library OS 中。

## 方法与技术要点

- **接口与威胁模型**：安全虚拟盘对外就是标准块设备，内部负责加解密；对手可嗅探、篡改、回滚、崩溃 TEE，作者不处理 DoS、侧信道与整盘回滚。
- **沿用 SGX-PFS 的 MHT**：每个受保护文件由 MHT、安全内存中的定长缓存与 recovery journal 组成，节点落盘时做认证加密（AES-GCM），非叶节点保存子节点的密钥与 MAC，metadata 节点保护根，从而同时给出机密性、完整性与新鲜性。
- **内部提交**：在 sync（flush）发生时触发一次显式 commit，把此刻之前的写确定为已提交；被 cache 逐出但未经 sync 的写保持未提交状态。
- **恢复语义**：崩溃恢复只从 recovery journal 回放已提交的写，未提交的逐出写被丢弃，因此盘上不会留下可被重放的半提交状态。
- **兼容性来源**：提交点挂在既有的 flush 语义上，上层应用与文件系统无需感知，仍按原来的 sync 语义工作。

## 评估与主要结果

- **对比设置**：trace 驱动的负载，与 SGX-PFS 对比；安全属性对照中 dm-crypt 加 dm-integrity 只有机密性与完整性，SGX-PFS 是 CIFC，AtomicDisk 是唯一同时满足机密性、完整性、新鲜性、一致性与原子性（CIFCA）的方案。
- **快照数量**：SGX-PFS 在每条 trace 上产生数十万个 vulnerable snapshot，均可被用于逐出攻击；AtomicDisk 只产生恰好一个有效状态，且由一次 sync 造成。
- **性能**：trace 驱动的对比中，AtomicDisk 的吞吐与 SGX-PFS 相当或更好。
