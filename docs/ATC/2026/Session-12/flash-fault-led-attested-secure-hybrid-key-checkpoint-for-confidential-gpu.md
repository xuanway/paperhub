# FLASH: Fault-Led, Attested, Secure Hybrid-Key Checkpoint for Confidential GPU

**中文标题**：FLASH：面向机密 GPU 的故障引导、可认证的安全混合密钥检查点

**所属 Session**：[Session 12: Security and Privacy](index.md) · [ATC 2026](../index.md)

**作者**：Jonghyun Lee (University of Southern California), Taewoon Kang (Korea University), Pratheek B (NVIDIA), Yongqin Wang (Roblox), Rachit Rajat (NVIDIA), Mengyuan Li (USC), Gunjae Koo (Korea University), Daniel Wong (University of California, Riverside), Murali Annavaram (USC)

## 英文摘要
GPU Confidential Computing (CC) enables secure LLM inference in production, combining a CPU TEE with NVIDIA’s GPU TEE to protect models and user data from a malicious cloud operator. As long-running LLMs are failure-prone, traditional cloud systems rely on backups, and live migration using checkpoint and restore to deal with failures. In particular, during LLM serving, GPUs build up a massive key-value (KV) cache that accelerates the decode process. But when using GPU CC, these recovery methods fail, as the GPU’s memory state, such as the KV cache, can’t be efficiently checkpointed. Checkpointing GPU memory requires encrypting the GPU data and transmitting to the CPU over the PCIe, which the CPU then decrypts using its shared key with the GPU. This encryption and decryption sequence over the PCIe leads to a 5.5× bandwidth penalty. The decrypted data is then re-encrypted with a new set of keys shared by the CPU and a destination server which adds overhead to the already-long checkpoint latency. LLM serving is stalled for the entire duration of checkpointing; a secure full-dump of an 80 GB H100 memory takes roughly 11 s. Alternatively, tracking write operations and selectively checkpointing these written pages is a preferable path, as only a small fraction of the KV cache is updated after each decode round. Current GPUs, however, lack the ability to track dirty pages. We present FLASH, a checkpoint/recovery (C/R) system for GPU CC that is both secure (providing confidentiality, integrity, and freshness against a malicious operator) and low latency. FLASH eliminates needless decryption of GPU state during checkpoint creation. FLASH preserves the GPU-encrypted HBM data as is without decryption. The CPU then creates a heterogeneous encryption package: (1) the CPU’s own memory state and the key used to encrypt the GPU CC is encrypted into a single bundle using keys shared by the CPU and a destination server that stores the checkpoint. (2) The GPU-encrypted HBM data is preserved as a second bundle within this heterogeneous package. This approach eliminates redundant decrypt-then-reencrypt overheads for GPU CC state. FLASH also presents a novel approach to track dirty pages to enable incremental checkpointing. FLASH enhances the GPU’s unified virtual memory (UVM) driver to downgrade any GPU page that is already checkpointed to a read-only page. It then uses the write fault mechanism to track modified pages at a 2 MB granularity. This approach requires no source code modifications to the LLM code base. Lastly, FLASH classifies never-written allocations, such as model weights, and removes them from repeated checkpoint copies while continuing to track them for correctness. On an H100 with Intel TDX running vLLM, FLASH reduces checkpoint stall latency up to 9.4× over state-of-the-art GPU C/R systems.

## 中文摘要
GPU 机密计算（CC）将 CPU TEE 与 NVIDIA 的 GPU TEE 相结合，可在生产环境中安全地进行 LLM 推理，保护模型与用户数据免受恶意云运营商的侵害。由于长时间运行的 LLM 容易发生故障，传统云系统依赖备份以及使用检查点与恢复的热迁移来应对故障。特别地，在 LLM 服务过程中，GPU 会积累大量的键值（KV）缓存以加速解码过程。但在使用 GPU CC 时，这些恢复方法会失效，因为 GPU 的内存状态（如 KV 缓存）无法被高效地做检查点。对 GPU 内存做检查点需要加密 GPU 数据并通过 PCIe 传输到 CPU，CPU 再用其与 GPU 的共享密钥解密。这一在 PCIe 上的加解密序列导致 5.5 倍的带宽损失。解密后的数据随后还要用 CPU 与目标服务器共享的新密钥重新加密，这为本已漫长的检查点延迟又增加了开销。LLM 服务在整个检查点期间都会停顿；对 80 GB H100 内存进行一次安全的全量转储大约需要 11 s。另一种更可取的路径是跟踪写操作并选择性地对这些被写的页做检查点，因为每轮解码之后只有很小一部分 KV 缓存被更新。然而，现有 GPU 缺乏跟踪脏页的能力。我们提出 FLASH，一个面向 GPU CC 的检查点/恢复（C/R）系统，它既安全（针对恶意运营商提供机密性、完整性和新鲜性），又具有低延迟。FLASH 在创建检查点时消除了对 GPU 状态不必要的解密。FLASH 原样保留 GPU 加密的 HBM 数据而不做解密。CPU 随后创建一个异构加密包：（1）CPU 自身的内存状态以及用于加密 GPU CC 的密钥，使用 CPU 与存放该检查点的目标服务器之间的共享密钥加密成一个单一的包。（2）GPU 加密的 HBM 数据作为该异构包中的第二个包原样保留。该方法消除了 GPU CC 状态上冗余的“先解密再重新加密”开销。FLASH 还提出了一种跟踪脏页以支持增量检查点的新方法。FLASH 增强 GPU 的统一虚拟内存（UVM）驱动，将任何已完成检查点的 GPU 页降级为只读页，然后利用写故障机制以 2 MB 的粒度跟踪被修改的页。该方法无需修改 LLM 代码库的源代码。最后，FLASH 对从未被写过的分配（如模型权重）进行分类，将其从重复的检查点拷贝中移除，同时继续跟踪它们以保证正确性。在运行 vLLM 且启用 Intel TDX 的 H100 上，FLASH 相比最先进的 GPU C/R 系统将检查点停顿延迟最多降低 9.4 倍。
