## 研究概要
本文面向RDMA解耦内存(DM)提出混合索引Sphinx，适配变长键ART结构。内存节点部署内层哈希表打破串行遍历依赖，计算端引入布谷过滤器精简缓存，规避一致性问题。YCS测试下最高性能达SOTA方案7.3倍，内存节点额外开销仅3.3%~4.9，计算端缓存占用极低。

## 背景和动机
1. 解耦内存架构计算、内存节点分离，依托RDMA远程访问索引，传统ART逐层串行遍历产生大量网络往返，延迟严重。
2. 现有SMART等DM专用ART采用完整节点缓存，计算端内存紧张时命中率差，且远程节点更新带来缓存一致性开销。
3. 节点级缓存为解决一致性需内存节点预分配超大空间，内存开销放大2~3倍，资源利用率低下。
4. 变长键场景树更深，串行遍历网络包数量激增，极易造成网卡带宽饱和、吞吐量瓶颈。
5. 缺少轻量、无一致性负担的计算端缓存方案，无法在极小缓存下大幅削减远程哈希读取次数。

## 相关工作
1. 原生ART索引：单机内存性能优异，但解耦内存下串行遍历网络往返过多，无法直接适配DM架构。
2. SMART（SOTA解耦ART）：缓存完整内层节点提升遍历速度，但缓存体积大，内存节点预分配机制空间开销极高，一致性维护成本大。
3. ROART/WORT持久化基数树：面向本地持久内存，未针对RDMA远程网络做往返优化。
4. 布谷过滤器类紧凑缓存：多用于单机KV，未与ART、解耦内存哈希表协同设计。
5. RDMA哈希索引：仅优化哈希结构，不支持变长键范围查询，无法替代ART索引场景。

## 本文解决方案
### 1 内存节点内层哈希表
以键完整前缀为键、节点地址与轻量元数据为值构建哈希条目，单条目仅8字节，额外内存仅3.3%~4.9%；将串行树遍历改为并行批量RDMA读取，消除层级访问依赖。
### 2 计算端精简过滤器缓存
基于布谷过滤器存储前缀存在性指纹，不缓存完整节点，天然无一致性问题；采用单热度位置换策略，极小内存即可过滤绝大多数无效哈希读取，单次查询仅需一次远程哈希访问。
### 3 轻量并发控制
读操作无锁；写采用节点粒度锁，叶子支持校验和原地更新，RDMA原子CAS完成8字节元数据修改，节点扩容失效标记规避临时不一致。
### 4 全套索引操作流水线
检索/插入/更新/删除统一走“过滤器查最长前缀→单次读哈希→取内层节点→叶子操作”流程，批量门铃合并RDMA请求减少往返。
### 5 适配变长键路径压缩
哈希表兼容ART路径压缩特性，过滤器精准匹配压缩后长前缀，长邮箱类变长键收益提升最显著。

## 实验分析
1. 测试环境：三节点RDMA解耦集群，100G网卡，对比原生ART、SMART、大容量SMART+C；数据集u64定长、email变长。
2. 吞吐量：各类YCSB负载下Sphinx优于基线，email数据集最高达SMART的7.3倍；范围查询与基线性能接近。
3. 扩展性：随并发worker提升吞吐量持续上涨，延迟远低于竞品，变长键场景优势更大。
4. 空间开销：内存节点哈希表增量极低，SMART内存占用是Sphinx的2.1~3倍；计算端仅20MB缓存即超越200MB SMART+C。
5. 缓存效果：过滤器假阳性低于1%，几乎所有查询仅单次远程哈希读取，网卡带宽压力大幅降低。

## 研究启发
1. 解耦内存索引性能瓶颈是串行树遍历，用哈希表打破层级访问依赖是核心优化思路。
2. 缓存无需存储完整节点，仅存储存在性紧凑过滤器可零一致性代价、大幅节省计算端内存。
3. 优化需分层兼顾：内存侧少量哈希空间开销，换取网络往返与计算端缓存双重收益。
4. 变长、深层索引场景传统遍历开销放大，Sphinx这类混合索引收益远大于定长索引。
5. RDMA原子操作与8字节轻量元数据结合，可实现低成本无锁读、细粒度锁写并发控制。
