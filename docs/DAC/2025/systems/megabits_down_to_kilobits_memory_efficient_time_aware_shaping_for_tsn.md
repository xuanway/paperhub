## 研究概要
本文面向TSN标准TAS时间感知整形器内存爆炸问题，提出METAS内存高效架构。摒弃传统逐帧存储门控表，采用每流持久规则+帧临时规则动态生成方案，搭配PIFO硬件队列。FPGA实测支持1024流时内存从14.34Mbits降至288Kbits，仅小幅增加逻辑，时延抖动维持微/纳秒级实时性能。

## 背景和动机
1. TSN工业/车载场景TAS采用逐帧门控规则，每个帧占用2条表项，超周期内帧数量巨大，门控表内存可达十几Mbits，超出FPGA片上BRAM容量。
2. 超周期为所有流周期最小公倍数，短周期流会产生海量帧，传统方案内存开销随帧数线性暴涨，62.94%工业流量配置内存溢出。
3. 片上SRAM用于转发、缓存等核心模块，TAS占用大量内存会挤占其他硬件资源，提升芯片面积与功耗。
4. 现有门控优化仅合并连续帧，仍未解决逐帧存储根源问题，还会引入额外抖动；缺少面向流的轻量化硬件设计。
5. 工业实时业务要求严格微秒时延、纳秒抖动，内存优化不能损害流量调度实时性。

## 相关工作
1. TAS门控表生成算法：侧重离线调度规划，未解决门控表硬件存储开销大的缺陷。
2. 帧合并优化方案：将连续帧合并单条规则，仅小幅缩减条目，破坏时序确定性，引入抖动。
3. TSN流量监管优化：采用每流存储，但仅适配监管模块，无法迁移至TAS整形。
4. PIFO优先级队列：支持任意位置入队、线速排序，但现有研究未结合TAS时序调度场景。
5. 商用TSN交换芯片：每流规则支持流种类有限，多周期混合流量场景扩展性差。

## 本文解决方案
### 1 每流存储核心思路
放弃逐帧门控表，SRAM仅存储每流持久规则（前帧发送时间、周期、序列号）；帧到达时硬件动态生成临时发送规则，传输完成即释放临时条目。
### 2 四大硬件组件协同架构
- 持久门控表：双端口RAM，O(1)按流索引，记录prTxTime、period、prSeqNo，处理丢包时序校正；
- 临时规则生成器：分无丢包/丢包两套时序计算逻辑，仅简单加减模运算，硬件开销极低；
- PIFO排序队列：寄存器浅队列（深度10），按发送时刻排序，处理跨超周期时序偏移；
- PIFO门控单元：对比当前时间与队首发送时刻，精准开关队列传输帧。
### 3 丢包时序校正机制
利用帧序列号检测丢包，自动跳过丢失周期修正发送时间，保证调度时序连续性。
### 4 跨超周期排序修正
临时规则排序时自动叠加超周期偏移，队列循环时回减，避免时序调度错乱。

## 实验分析
1. 硬件平台：Xilinx Kintex-7 FPGA，集成OpenTSN开源交换机，对比传统naive-TAS基线。
2. 内存开销：支持1024流时传统方案占用14.34Mbits（91.69%BRAM），METAS仅288Kbits；流规模提升内存几乎无增长。
3. 逻辑资源：LUT增加1.56%、FF增加0.11%，PIFO寄存器占用不足0.19%，硬件代价极小。
4. 实时性能：哑铃拓扑实测端到端时延微秒级，抖动仅120~140ns，满足工业硬实时指标。
5. 扩展性：短周期流占比提升，传统内存暴增，METAS不受帧数量影响，适配混合周期工业流量。

## 研究启发
1. TAS内存瓶颈根源是逐帧存储门控表，利用流周期性切换每流存储范式可从根源削减片上内存。
2. 把静态表开销转为少量动态临时条目，以极小逻辑开销换取百倍内存节省，是嵌入式交换硬件高效折中思路。
3. 浅深度PIFO完全适配TSN缓存帧少的场景，相比堆排序、最小堆更适合线速硬件时序调度。
4. 时序计算只需简单算术单元，无需复杂乘除器，可低成本集成到现有TSN交换机流水线。
5. 优化方案需兼容现有离线流量规划算法，仅要求流传输周期性，工程落地改造成本低。
