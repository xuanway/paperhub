## 研究概要
本文提出混合嵌入框架HDE解决DLRM推荐模型嵌入表内存爆炸问题。依据访问热度划分冷热嵌入，热向量存紧凑查表，冷向量由DHE哈希网络在线生成；CPU查表与GPU网络并行隐藏计算延迟。Criteo/Avazu数据集内存仅为基线5%，AUC损失极小，训练时延与原生FDE基本持平。

## 背景和动机
1. 工业DLRM嵌入表可达TB级，海量稀疏特征造成内存瓶颈，查表成为训练推理核心耗时环节。
2. 特征访问符合长尾分布：不足10%热嵌入承载80%访问，90%冷向量占用大量内存却对精度影响微弱。
3. 现有DHE、组合嵌入CE全量替换嵌入表，大幅拉长计算时延；低比特量化、混合维度会带来明显精度衰减。
4. 单一软硬件资源下查表与特征生成串行执行，冷向量网络计算引入显著额外延迟。
5. 多字段独立嵌入处理重复索引分类、重组逻辑，产生大量冗余预处理开销。

## 相关工作
1. 原生FDE：全维度独立嵌入表，精度最优但内存开销极大，工业部署受限。
2. 哈希类嵌入（D/CE）：全量用哈希网络替代查表，内存缩减但计算延迟暴涨，训练速度大幅下降。
3. 混合维度/剪枝嵌入：按热度分配不同维度，存在超参敏感、训练开销高问题。
4. 异构内存调度：仅冷热向量分存高速/低速存储，未从模型表征层面削减嵌入参数量。
5. 低精度量化嵌入：通过比特压缩减内存，会造成点击率预测AUC明显下降。

## 本文解决方案
### 1 冷热嵌入分层表征策略
离线统计特征访问频次，取前5%作为热向量存入CPU紧凑嵌入表；剩余冷向量舍弃存储，由GPU端D哈希网络实时生成，仅牺牲少量精度换取95%内存压缩。
### 2 DHE深度哈希冷向量生成网络
多哈希函数生成标识向量输入多层FC，无固定存储表；网络参数量远小于完整嵌入表，可灵活调整网络容量平衡精度与算力。
### 3 CPU-GPU并行流水线
CPU执行热嵌入查表，GPU同步运行DHE冷向量计算，两者并行重叠掩盖网络计算延迟，大幅降低串行等待耗时。
### 4 全局聚合嵌入优化
多字段嵌入表合并为统一大表，批量归集冷热索引，一次性查表/网络计算，消除逐字段重复分类、重组冗余操作。
### 5 轻量化预处理流程
仅对超大字段执行冷热划分，小规模字段直接查表跳过哈希计算；批量掩码预处理、索引偏移转换降低调度开销。

## 实验分析
1. 实验环境：AMD EPYC CPU + A100 GPU，Criteo、Avazu两大CTR基准，对比FDE、CE、DHE。
2. 内存压缩：HDE嵌入参数量仅为基线FDE的5.0%~5.1，压缩20倍。
3. 精度表现：AUC与FDE几乎无差距，Avazu数据集AUC小幅提升，显著优于DHE、CE。
4. 训练时延：HDE总耗时和原生FDE接近，CPU-GPU计算重叠率达81.95%，远高于基线24.01%；DHE时延是HDE近10倍。
5. 消融验证：冷热划分+聚合嵌入并行两大模块缺一不可，全量DHE会带来严重延迟开销。

## 研究启发
1. 推荐特征长尾访问特性是核心优化抓手，无需全量替换嵌入，仅处理低影响冷向量即可实现极致内存压缩。
2 CPU-GPU异构并行可抵消哈希网络额外计算，将冷向量生成延迟完全隐藏在查表周期内。
3 逐字段独立嵌入处理冗余严重，全局聚合批量索引处理能大幅削减预处理开销。
4 全哈希网络方案存在算力缺陷，冷热混合表征兼顾内存、精度、时延三方权衡。
5 冷向量对模型预测贡献有限，轻量化神经网络可高精度拟合其表征，无需持久存储。
